## Parent Context

The parent feature defines four tasks. Tasks 1 and 2 are complete:
- Task 1 established `.requestMatchers("/agent/**").hasRole("EMPLOYEE")` in `SecurityConfig` and added three `@WithMockUser` security tests to `SecurityAuthorizationTest`. The employee test asserts `isNotFound()` (404) with a forward-reference comment that **Task 3 must update it to assert `isOk()` once the controller exists**.
- Task 2 created `AgentEntity`, DTOs, `AgentForm`, `AgentMapper`, `AgentRepository`, and generated `QAgentEntity`.

Task 3 covers the business logic and exposure layer. Key parent decisions that govern this task:

- **`DefaultServiceImplements.pageableFactory` and `queryPredicateBuilder` are `private`.** They must be changed to `protected` before `AgentService` can access them to override `getListPage()`.
- **`AgentService.getAll()` must throw `ResponseStatusException(METHOD_NOT_ALLOWED)`.** An unpaginated full-table dump has no valid use case for an ownership-scoped resource. `POST /agent/list` is the correct paginated, scoped alternative.
- **`AgentService.getListPage()` ANDs an ownership predicate** (`QAgentEntity.agentEntity.owner.id.eq(currentEmployee.getId())`) with the user-supplied filter predicate so employees only ever see their own agents.
- **Full-state PUT semantics for `update()`.** All form fields are applied unconditionally. Nullable fields (`description`, `recurrentPrompt`) are cleared when null is sent. `@Valid` at the controller ensures `name` and `initPrompt` are non-blank.
- **`DefaultServiceImplements.update()` is a no-op.** `AgentService` must override `update()` completely — do not call `super.update()`.
- **Ownership violations return `ItemNotFoundException` (404).** The service loads agents via `findByIdAndOwnerId(id, currentEmployee.getId())` so "not found" and "not owner" are the same response.
- **Name uniqueness is per-employee at the service layer.** `existsByNameAndOwnerId(name, ownerId)` enforces this; duplicate names for different employees are allowed.
- **`@PreAuthorize("hasRole('EMPLOYEE')")` on all `AgentService` public methods** for defense-in-depth.
- **No `@Transactional` on individual service methods.** Transaction coverage is inherited from the class-level `@Transactional(rollbackFor = {...})` on `DefaultServiceImplements`. This mirrors `LlmModelService`.
- **ADR-006** declares `AgentEntity` as the FK target for `ConversationEntity.agent`. `AgentEntity` itself has no cascade constraints yet — those are deferred to the Conversation feature.
- **ADR-008** confirms `initPrompt` and `recurrentPrompt` live on `AgentEntity`, not as persisted messages.
- **ADR-009** confirms `AgentController` must use `Long` as the ID type parameter.

## Implementation Details

### Approach

**SOLID analysis:**
- **SRP**: `AgentService` owns Agent business rules (ownership enforcement, name uniqueness, list scoping). `AgentQueryProfile` owns the field-declaration contract for filtering/sorting. `AgentController` owns HTTP routing only — no business logic.
- **OCP**: `AgentService` extends `DefaultServiceImplements` by overriding only the methods that need domain-specific behavior. `AgentController` extends `DefaultController` with no new endpoints.
- **DIP**: `AgentService` depends on `AgentRepository` (via `DefaultRepository` abstraction) and `AgentMapper` (via `DefaultMapper` abstraction). `AgentController` depends on `DefaultService` abstraction.
- **Depth**: `AgentService` is deep — a large body of ownership and uniqueness logic hides behind six method signatures. `AgentQueryProfile` is shallow by design — field declarations are inherently coordinative, not logic-holding. `AgentController` is maximally shallow — it delegates entirely to the service.

**TDD cycle 1 — Service:**
1. **RED**: Write `AgentServiceCrudIntegrationTest`. Tests compile (service interface exists via `DefaultService`) but all calls to `agentService` methods fail because `AgentService` does not exist as a Spring bean.
2. **GREEN**: Create `AgentQueryProfile`, modify `DefaultServiceImplements` (private → protected), create `AgentService`. All service tests pass.

**TDD cycle 2 — Controller:**
1. **Modify**: Update `SecurityAuthorizationTest.employeeRequestToAgentEndpointPassesSecurity()` — switch from `@WithMockUser` + `isNotFound()` to employee JWT + `isOk()`.
2. **RED**: Write `AgentControllerTest`. Tests fail because no routes match (controller not yet registered). Note: the employee test in `SecurityAuthorizationTest` now also fails because it expects `isOk()` but the controller doesn't exist yet.
3. **GREEN**: Create `AgentController`. All controller tests and the updated security test pass.

**Why ownership predicate uses `BooleanBuilder`:**
`QueryPredicateBuilder.build(request, queryProfile)` returns a `BooleanBuilder` (implements `Predicate`). When the request has no filters, this is an empty `BooleanBuilder` whose `getValue()` is `null`. `new BooleanBuilder(basePredicate).and(ownerPredicate).getValue()` handles the null case correctly: the result is just `ownerPredicate` when no user filters exist, and `basePredicate AND ownerPredicate` when user filters exist.

## Step-by-Step Implementation

### Step 1: Modify DefaultServiceImplements — `private` → `protected`

**Goal:** Allow `AgentService.getListPage()` to access `pageableFactory` and `queryPredicateBuilder` without duplicate injection.

**Dependencies:** None — this is a pure modifier change with no behavior change.

- [ ] Open `DefaultServiceImplements.java`
- [ ] Change `private final PageableFactory<ENTITY> pageableFactory;` to `protected final PageableFactory<ENTITY> pageableFactory;`
- [ ] Change `private final QueryPredicateBuilder<ENTITY> queryPredicateBuilder;` to `protected final QueryPredicateBuilder<ENTITY> queryPredicateBuilder;`
- [ ] Compile and confirm: `./mvnw compile` from `backend/` — 0 errors
- [ ] Run `./mvnw test -Dtest=LlmModelServiceCrudIntegrationTest` to confirm no regression in the service that previously used these private fields indirectly

**Why this step is critical:** Without this change, `AgentService.getListPage()` cannot access the inherited `pageableFactory` and `queryPredicateBuilder`. The alternative (injecting them again in `AgentService`) would violate SRP — the parent class already owns these dependencies.

#### Implementation

Change lines 37–38 in `DefaultServiceImplements.java`:

```java
// Before:
private final PageableFactory<ENTITY> pageableFactory;
private final QueryPredicateBuilder<ENTITY> queryPredicateBuilder;

// After:
protected final PageableFactory<ENTITY> pageableFactory;
protected final QueryPredicateBuilder<ENTITY> queryPredicateBuilder;
```

#### Edge Cases

1. **No behavior change:** `protected` still prevents access from outside the class hierarchy. All existing subclasses (`LlmModelService`, `EmployeeService`, `AdminService`, `ClientService`, `AppSettingsService`) had no direct field access to these — they used `super.getListPage()` or overrode it. None are affected.

#### Edge Cases

1. **`@WithMockUser` username must match DB row:** `AuthUserUtil.getAuthUserEmployeeEntity()` calls `baseUserRepository.findByUsername(username)`. With `@WithMockUser(username = "agent-svc-owner@test.com")`, Spring creates a `UserDetails` principal with that username. `getAuthUsername()` extracts it via `((UserDetails) principal).getUsername()`. The `ownerEmployee` persisted in `@BeforeEach` has `username = "agent-svc-owner@test.com"` — they match.
2. **`deleteAll()` order:** Agents must be deleted before employees because `AgentEntity.owner` is an FK to `EmployeeEntity` (`nullable = false`). Deleting the employee first would cause a FK constraint violation in the DB.
3. **`getListPageDefaultSortIsCreatedAtDesc` timing:** Both agents are inserted in the same test method, so `createdAt` may be within the same millisecond on fast hardware. In practice, H2 resolves this correctly; if flakiness occurs in CI, add a 1 ms `Thread.sleep()` between inserts (document it as a test-timing workaround, not application logic).
4. **Cross-owner tests create employees directly via `employeeRepository`:** These tests bypass `EmployeeService` to avoid the `@WithMockUser(roles = "ADMIN")` requirement for that service. Direct repository saves are safe here — the goal is to seed test data, not test `EmployeeService`.

```java
package com.agentForgeBackend.models.agent;

import com.agentForgeBackend.exceptions.InvalidInsertDetails;
import com.agentForgeBackend.exceptions.ItemAlreadyExist;
import com.agentForgeBackend.exceptions.ItemNotFoundException;
import com.agentForgeBackend.shared.defaultImplements.DefaultServiceImplements;
import com.agentForgeBackend.shared.query.PageableFactory;
import com.agentForgeBackend.shared.query.PageableRequest;
import com.agentForgeBackend.shared.query.QueryPredicateBuilder;
import com.agentForgeBackend.shared.tools.AuthUserUtil;
import com.agentForgeBackend.models.hq.employee.EmployeeEntity;
import com.querydsl.core.BooleanBuilder;
import com.querydsl.core.types.Predicate;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.http.HttpStatus;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

import java.util.Collection;

@Service
public class AgentService extends DefaultServiceImplements<AgentDTO, AgentMiniDTO, AgentListDTO, AgentForm, AgentEntity, Long> {

    private final AgentRepository agentRepository;
    private final AgentMapper agentMapper;
    private final AuthUserUtil authUserUtil;

    public AgentService(
            AgentRepository repository,
            AgentMapper mapper,
            AgentQueryProfile queryProfile,
            PageableFactory<AgentEntity> pageableFactory,
            QueryPredicateBuilder<AgentEntity> queryPredicateBuilder,
            AuthUserUtil authUserUtil
    ) {
        super(repository, mapper, queryProfile, pageableFactory, queryPredicateBuilder);
        this.agentRepository = repository;
        this.agentMapper = mapper;
        this.authUserUtil = authUserUtil;
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public AgentMiniDTO insert(AgentForm form) throws ItemNotFoundException, ItemAlreadyExist, InvalidInsertDetails {
        if (form == null || form.getName() == null || form.getName().isBlank()) {
            throw new InvalidInsertDetails("Agent name is required.");
        }
        if (form.getInitPrompt() == null || form.getInitPrompt().isBlank()) {
            throw new InvalidInsertDetails("Agent initPrompt is required.");
        }
        EmployeeEntity currentEmployee = currentEmployee();
        if (agentRepository.existsByNameAndOwnerId(form.getName(), currentEmployee.getId())) {
            throw new ItemAlreadyExist("An agent named '" + form.getName() + "' already exists.");
        }
        AgentEntity entity = agentMapper.toEntity(form);
        entity.setOwner(currentEmployee);
        return agentMapper.toSmallDTO(agentRepository.save(entity));
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public AgentDTO getOne(Long id) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        return agentRepository.findByIdAndOwnerId(id, currentEmployee.getId())
                .map(agentMapper::toDTO)
                .orElseThrow(ItemNotFoundException::new);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public AgentDTO update(Long id, AgentForm form) throws ItemNotFoundException, InvalidInsertDetails, ItemAlreadyExist {
        // REVIEW-FIX: guard against NPE when update() is called directly (bypassing @Valid)
        if (form == null || form.getName() == null || form.getName().isBlank()) {
            throw new InvalidInsertDetails("Agent name is required.");
        }
        if (form.getInitPrompt() == null || form.getInitPrompt().isBlank()) {
            throw new InvalidInsertDetails("Agent initPrompt is required.");
        }
        EmployeeEntity currentEmployee = currentEmployee();
        AgentEntity entity = agentRepository.findByIdAndOwnerId(id, currentEmployee.getId())
                .orElseThrow(ItemNotFoundException::new);
        // Name uniqueness check: skip if name is unchanged
        if (!form.getName().equals(entity.getName()) &&
                agentRepository.existsByNameAndOwnerId(form.getName(), currentEmployee.getId())) {
            throw new ItemAlreadyExist("An agent named '" + form.getName() + "' already exists.");
        }
        // Full-state PUT semantics: apply all fields unconditionally
        entity.setName(form.getName());
        entity.setInitPrompt(form.getInitPrompt());
        entity.setDescription(form.getDescription());         // null clears the field
        entity.setRecurrentPrompt(form.getRecurrentPrompt()); // null clears the field
        return agentMapper.toDTO(agentRepository.save(entity));
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public AgentDTO delete(Long id) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        AgentEntity entity = agentRepository.findByIdAndOwnerId(id, currentEmployee.getId())
                .orElseThrow(ItemNotFoundException::new);
        agentRepository.delete(entity);
        return agentMapper.toDTO(entity);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public Page<AgentListDTO> getListPage(PageableRequest request) {
        EmployeeEntity currentEmployee = currentEmployee();
        // AND the user-supplied predicate with the ownership predicate so employees only see their agents
        Predicate basePredicate = queryPredicateBuilder.build(request, queryProfile);
        Predicate ownerPredicate = QAgentEntity.agentEntity.owner.id.eq(currentEmployee.getId());
        // BooleanBuilder(null) is a valid empty builder; getValue() handles the empty-filter case
        Predicate combined = new BooleanBuilder(basePredicate).and(ownerPredicate).getValue();
        PageRequest pageable = pageableFactory.create(request, queryProfile);
        return agentRepository.findAll(combined, pageable).map(agentMapper::toListDTO);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public Collection<AgentDTO> getAll() {
        throw new ResponseStatusException(HttpStatus.METHOD_NOT_ALLOWED,
                "Use POST /agent/list for scoped agent retrieval.");
    }

    private EmployeeEntity currentEmployee() {
        return authUserUtil.getAuthUserEmployeeEntity()
                .orElseThrow(() -> new ItemNotFoundException("Authenticated employee not found."));
    }
}
```

#### Edge Cases

1. **`currentEmployee()` throws `ItemNotFoundException` if the principal isn't in the DB.** This can happen in tests with stale user data or during manual testing with an expired JWT for a deleted employee. The `ItemNotFoundException` maps to 404, which is the correct response — no principal means no access.
2. **`getListPage` with no filters:** `queryPredicateBuilder.build(request, queryProfile)` returns an empty `BooleanBuilder` (its `getValue()` is `null`). `new BooleanBuilder(null).and(ownerPredicate).getValue()` returns `ownerPredicate` alone — correct behavior.
3. **`update()` null-safety on nullable fields:** `form.getDescription()` and `form.getRecurrentPrompt()` may be null (clear-field semantics). Setting them on the entity with `null` and saving causes Hibernate to issue an UPDATE that nulls those columns. This is intentional full-state PUT behavior.
4. **`getAll()` and transaction rollback:** `ResponseStatusException` is not in `DefaultServiceImplements`'s `@Transactional(rollbackFor = {...})`. However, since `getAll()` only throws without doing any DB work, there is nothing to roll back.
5. **Defense-in-depth ordering:** The HTTP security rule (`hasRole("EMPLOYEE")` at the route level) fires first; `@PreAuthorize("hasRole('EMPLOYEE')")` fires second at method invocation time. Both must be satisfied. Admins blocked at HTTP; Clients blocked at HTTP. No `agentService` method is reachable by non-employees.

## Design Decisions

**Decision 1: Change `DefaultServiceImplements` fields from `private` to `protected`**
- **Why:** `AgentService.getListPage()` needs `pageableFactory` and `queryPredicateBuilder` to AND the ownership predicate with user-supplied filters. The alternative (duplicating the dependencies in `AgentService`'s constructor and storing them separately) violates SRP — the parent class already owns these. `protected` preserves encapsulation against external callers while allowing the subclass hierarchy access.
- **Alternatives considered:** Duplicate `pageableFactory` and `queryPredicateBuilder` fields in `AgentService`. Rejected — creates two sources of truth for the same injected bean; also violates DRY.

**Decision 2: `currentEmployee()` private helper throws `ItemNotFoundException`, not `IllegalStateException`**
- **Why:** When `authUserUtil.getAuthUserEmployeeEntity()` returns empty in a production context, it means the JWT is valid but the employee was deleted since the token was issued. `ItemNotFoundException` (404) is the least-information response — consistent with the feature's principle of not leaking system state. `IllegalStateException` would return 500, which is incorrect.
- **Alternatives considered:** Throw `AccessDeniedException` (403). Rejected — ownership violations use 404 by convention (per parent feature); this case is equivalent.

**Decision 3: `getAll()` throws `ResponseStatusException(METHOD_NOT_ALLOWED)` rather than hiding the route**
- **Why:** `DefaultController.getAll()` is mapped to `GET /agent`. It is cleaner to expose the endpoint with an explicit 405 than to fight the base class mapping. Callers learn immediately to use `POST /agent/list` instead. Removing the endpoint from the route table would require overriding at the controller level (adding a new `@GetMapping("")` that shadows the parent's), which is more complexity for the same result.
- **Alternatives considered:** Override `getAll()` at the controller level to return 405 directly. Rejected — business rules belong in the service, not the controller. ADR-006's principle of keeping domain behavior in the service layer applies.

**Decision 4: Full-state PUT semantics for `update()`**
- **Why:** REST PUT is defined as a full-state replacement. `@Valid` guarantees `name` and `initPrompt` are non-blank before the service executes. Nullable fields (`description`, `recurrentPrompt`) sent as `null` correctly clear the field. This avoids the complexity of patch-semantics (which null means "leave unchanged" vs. "clear"?), which is semantically ambiguous without an explicit PATCH verb.
- **Alternatives considered:** PATCH semantics (null means skip, explicit sentinel for clear). Rejected — unnecessary complexity for a resource that employees directly manage; full-state PUT is standard and self-documenting.

**Decision 5: Service tests use `@WithMockUser(username = ..., roles = "EMPLOYEE")` + real DB employee**
- **Why:** `AgentService` calls `AuthUserUtil.getAuthUserEmployeeEntity()` which reads the DB via `BaseUserRepository.findByUsername(username)`. The username comes from the SecurityContext principal. `@WithMockUser` sets a `UserDetails` principal — `getUsername()` returns the specified username. If the DB has an employee with that username, `getAuthUserEmployeeEntity()` finds them. This is the simplest way to test ownership enforcement without starting a full HTTP server or mocking `AuthUserUtil`.
- **Alternatives considered:** `SecurityContextHolder.setContext()` with a manually built `Authentication`. Rejected — more boilerplate, less readable, and not the pattern established by `LlmModelServiceCrudIntegrationTest`.

## Post-Review Notes

**Compile fix — `currentEmployee()` checked exception in `getListPage()`:**
The task document's `currentEmployee()` helper throws `ItemNotFoundException` (a checked exception). Methods `insert()`, `getOne()`, `update()`, and `delete()` all declare `throws ItemNotFoundException` so they can call `currentEmployee()` directly. However, `getListPage()` inherits the `DefaultService.getListPage()` contract which only declares `throws InvalidQueryRequestException` — adding `throws ItemNotFoundException` to the override is not permitted by Java's checked exception rules. Resolution: `getListPage()` resolves the current employee inline using `authUserUtil.getAuthUserEmployeeEntity().orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, ...))` — `ResponseStatusException` is a `RuntimeException` so it requires no declaration, and Spring's `ResponseStatusExceptionResolver` maps it to HTTP 404 correctly. The `currentEmployee()` private helper retains `throws ItemNotFoundException` for use by the other four methods.
