## Goal

Wire the Conversation domain into a working, employee-scoped REST API: `ConversationQueryProfile` (dynamic filter/sort declarations), `ConversationService` (all ownership-enforced CRUD plus two custom PATCH operations), and `ConversationController` (inherited endpoints + `PATCH /{id}/model` and `PATCH /{id}/title`). After this task, employees can create, retrieve, list, delete, rename, and switch the model of their own conversations via JWT-authenticated REST calls.

---

## Parent Context

The parent feature defines four tasks. Tasks 1 (security baseline) and 2 (domain foundation) are complete. This task implements the business-logic layer on top of the persistence foundation from Task 2.

Key parent decisions that govern this task:

- **Ownership enforcement at the service layer**: every single-entity operation uses `conversationRepository.findByIdAndEmployeeId(id, currentEmployee.getId())`. Ownership violations surface as `ItemNotFoundException` (404, not 403) so employees cannot enumerate other employees' conversation IDs.
- **Model validation on every create/switch**: `llmModelRepository.findByIdAndIsEnabledTrue(modelId)` — throws `ItemNotFoundException` if the model does not exist or is disabled.
- **Agent ownership validation on create**: if `form.getAgentId()` is non-null, `agentRepository.findByIdAndOwnerId(agentId, currentEmployee.getId())` — throws `ItemNotFoundException` if absent or not owned.
- **Title auto-generation**: if `form.getTitle()` is null or blank, the service sets `"New Conversation"`. The mapper passes `title` through without defaulting.
- **`getAll()` → 405**: override to throw `ResponseStatusException(METHOD_NOT_ALLOWED)` — no unbounded list dump.
- **`update()` → 405**: override to throw `ResponseStatusException(METHOD_NOT_ALLOWED)` — mutations flow through the two PATCH endpoints.
- **List scoped to authenticated employee**: `getListPage()` ANDs an ownership predicate with the user-supplied predicate — same BooleanBuilder pattern as `AgentService`.
- **Default list sort**: `updatedAt DESC` — most recently touched conversations first.
- **`agentId` filter-only in QueryProfile**: `agent.id` is filterable but NOT sortable. Registered with `.nullable()` to enable `IS_NULL`/`IS_NOT_NULL` operators (for "show general conversations only").
- **Controller dual-injection pattern**: `ConversationController` follows `LlmModelController`: `super(service)` wires the inherited CRUD; an explicit `conversationService` field reaches custom PATCH methods, since the inherited `defaultService` is typed as `DefaultService<...>` and cannot call domain-specific methods.
- **`@PreAuthorize("hasRole('EMPLOYEE')")` on all public service methods**: defense-in-depth on top of the HTTP-layer gate added in Task 1.
- **`LlmModelService` is NOT injectable** — all its methods are gated by `@PreAuthorize("hasRole('ADMIN')")`. `ConversationService` injects `LlmModelRepository` directly for the enabled-model lookup. This was established in Task 2 when `findByIdAndIsEnabledTrue` was added.
- **`SecurityAuthorizationTest` setUp update** (forward-referenced in Task 1): `ConversationControllerTest` runs alphabetically before `SecurityAuthorizationTest` ("Co" < "Se") and leaves committed conversations in H2. `SecurityAuthorizationTest.setUp()` must add `conversationRepository.deleteAll(); conversationRepository.flush();` BEFORE `agentRepository.deleteAll()` — otherwise `employeeRepository.deleteAll()` throws a FK constraint violation on `conversation.employee_id` (non-nullable). The `employeeRequestToConversationEndpointPassesSecurity` test must also be updated from `@WithMockUser isNotFound()` to real JWT `isOk()` now that the controller exists.

## Implementation Details

### Approach

**SOLID analysis:**

- **ConversationQueryProfile** (SRP + Depth): one responsibility — declare which fields are queryable and how to sort by default. The entire QueryDSL predicate-building machinery (operator dispatch, type conversion, null-handling) hides behind the profile's `fields()` map. Pure data declaration; no logic.
- **ConversationService** (SRP + DIP + Depth): one responsibility — own Conversation business rules. Depends on abstractions: `ConversationRepository` (via `DefaultRepository`), `ConversationMapper` (via `DefaultMapper`), `LlmModelRepository`, `AgentRepository`, `AuthUserUtil`. The depth is real: title auto-generation, ownership enforcement, model validation, agent ownership validation, and list scoping all concentrate here and would otherwise scatter across callers.
- **ConversationController** (SRP + thin coordinator): delegates to service; zero business logic. Dual-injection follows the LlmModelController pattern — the only pattern in this codebase for a controller with custom endpoints beyond the inherited CRUD surface.

**TDD order (two vertical cycles):**

1. **Service cycle** — RED: write `ConversationServiceIntegrationTest` (fails because `ConversationService` doesn't exist yet; `ConversationQueryProfile` is also missing so any QueryDSL path expression using the profile would fail at runtime). GREEN: create `ConversationQueryProfile`, then `ConversationService` — all service tests pass.
2. **Controller cycle** — RED: write `ConversationControllerTest` (all requests return 404 because no controller is mapped). GREEN: create `ConversationController`, update `SecurityAuthorizationTest` — all controller tests pass.

**`getListPage` ownership predicate pattern** (identical to AgentService):
```
basePredicate  = queryPredicateBuilder.build(request, queryProfile)
ownerPredicate = QConversationEntity.conversationEntity.employee.id.eq(currentEmployee.getId())
combined       = new BooleanBuilder(basePredicate).and(ownerPredicate).getValue()
```
`BooleanBuilder(null)` is a valid empty builder — `getValue()` handles the no-filter case. The `agentId` filter in the query profile uses `CONV.agent.id` (nested FK path) — it is handled transparently by the standard `QueryPredicateBuilder` via the `agentId` field registration; no manual predicate extraction is needed.

**`getAll()` and `update()` overrides**: both must throw `ResponseStatusException`. Do NOT call `super.getAll()` or `super.update()` — `super.update()` is a known no-op (see `known-issues.md`: "DefaultServiceImplements.update() loads the entity by ID but then saves the original entity without applying the form data").

**`switchModel` and `updateTitle`**: these are custom methods on `ConversationService` that are NOT part of the `DefaultService` interface. They are called directly from `ConversationController`'s PATCH mappings via the concrete `conversationService` field — not via the inherited `defaultService` field.

#### Implementation

```java
package com.agentForgeBackend.models.conversation;

import com.agentForgeBackend.shared.query.EntityQueryProfile;
import com.agentForgeBackend.shared.query.QueryableField;
import com.agentForgeBackend.shared.query.SortDirection;
import com.agentForgeBackend.shared.query.SortRequest;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;
import java.util.List;
import java.util.Map;

@Component
public class ConversationQueryProfile implements EntityQueryProfile<ConversationEntity> {

    private static final QConversationEntity CONV = QConversationEntity.conversationEntity;

    private static final Map<String, QueryableField<ConversationEntity, ?>> FIELDS = Map.of(
            "id",        QueryableField.<ConversationEntity, Long>number("id", CONV.id, Long.class).sortable("id"),
            "title",     QueryableField.<ConversationEntity>string("title", CONV.title).sortable("title"),
            "createdAt", QueryableField.<ConversationEntity, LocalDateTime>dateTime("createdAt", CONV.createdAt, LocalDateTime.class).sortable("createdAt"),
            "updatedAt", QueryableField.<ConversationEntity, LocalDateTime>dateTime("updatedAt", CONV.updatedAt, LocalDateTime.class).sortable("updatedAt"),
            // agentId: filterable only (not sortable). .nullable() adds IS_NULL / IS_NOT_NULL operators.
            // CONV.agent.id uses the nested FK path — QueryPredicateBuilder handles this transparently.
            "agentId",   QueryableField.<ConversationEntity, Long>number("agentId", CONV.agent.id, Long.class).nullable()
    );

    private static final List<SortRequest> DEFAULT_SORT = List.of(
            SortRequest.builder().field("updatedAt").direction(SortDirection.DESC).build()
    );

    @Override
    public Map<String, QueryableField<ConversationEntity, ?>> fields() {
        return FIELDS;
    }

    @Override
    public List<SortRequest> defaultSort() {
        return DEFAULT_SORT;
    }
}
```

#### Edge Cases

1. **`CONV.agent.id` nested path**: QueryDSL generates this path because `ConversationEntity.agent` is a `@ManyToOne` to `AgentEntity`, and `AgentEntity` has a field `id`. The path resolves to `conversation.agent_id` in SQL — no JOIN is generated unless other agent fields are referenced. For a null agent FK, the predicate `CONV.agent.id.eq(someId)` returns no rows (SQL: `WHERE agent_id = ?` returns false when `agent_id IS NULL`). The `.nullable()` call is what adds the `IS_NULL`/`IS_NOT_NULL` operators; without it, null-agent-FK rows are simply excluded from `EQUALS`/`IN` filter results — which is correct behavior.
2. **`agentId` is not sortable**: calling `.sortable("agentId")` would allow `sort: [{field: "agentId", direction: "ASC"}]` in the API, which sorts conversations by their agent's primary key — not meaningful. The feature document explicitly excludes sortability for this field. Do not add `.sortable()`.
3. **`employee` and `currentModel` are intentionally absent**: both are internal ownership/configuration FKs. `employee` is always auto-applied as the ownership predicate; filtering by `currentModel` is not a useful employee-facing query. Exposing them would allow employees to enumerate each other's conversation IDs via cross-field correlation.
4. **`Map.of` with 5 entries**: Java's `Map.of` overloads accept up to 10 key-value pairs. 5 entries is within the single-method-call limit; no `Map.ofEntries()` needed.
5. **Default sort `updatedAt DESC`**: most recently touched conversations first — standard UX pattern for chat session lists. Differs from `AgentQueryProfile` which defaults to `createdAt DESC`.

#### Edge Cases

1. **`@WithMockUser` username must match seeded employee's username**: `AuthUserUtil.getAuthUserEmployeeEntity()` calls `BaseUserRepository.findByUsernameAndRole(...)` — it looks up the principal's username in the DB. If the DB employee's username doesn't match the `@WithMockUser` username exactly, `getAuthUserEmployeeEntity()` returns `Optional.empty()` and the service throws `ItemNotFoundException` on every call.
2. **`appSettingsRepository.findFirstBy()` clears `defaultModel` FK**: `AppSettingsEntity.defaultModel` is a nullable FK to `LlmModelEntity`. Without clearing it, `llmModelRepository.deleteAll()` throws a FK constraint violation from `app_settings.default_model_id`.
3. **LLM model `modelId` unique constraint**: each setUp creates models with fixed `modelId` values (`"test/conv-svc-enabled"`, `"test/conv-svc-disabled"`). Since `llmModelRepository.deleteAll()` runs at the start of each setUp, the unique constraint is not violated between test methods.
4. **`conversationRepository.deleteAll()` before `agentRepository.deleteAll()`**: `conversation.agent_id` is a nullable FK to `agent` (with ON DELETE SET NULL on the DB constraint). However, Hibernate's `deleteAll()` issues individual `DELETE FROM conversation` statements that do not benefit from the DDL cascade — they hit the FK constraint if conversation rows referencing agents exist when agents are deleted. Deleting conversations first is the safe order.
5. **`getListPageRejectsAgentIdSortField` test**: `agentId` is registered without `.sortable()` in `ConversationQueryProfile`. The `QueryPredicateBuilder` (or `PageableFactory`) should reject a sort request on `agentId` with `InvalidQueryRequestException`. Verify this is consistent with how other non-sortable fields behave — if the implementation throws a different exception for "field registered but not sortable" vs "field not registered at all", adjust the assertion.

import com.agentForgeBackend.exceptions.InvalidInsertDetails;
import com.agentForgeBackend.exceptions.InvalidQueryRequestException;

import java.util.Collection;

@Service
public class ConversationService extends DefaultServiceImplements<ConversationDTO, ConversationMiniDTO, ConversationListDTO, ConversationForm, ConversationEntity, Long> {

    private final ConversationRepository conversationRepository;
    private final ConversationMapper conversationMapper;
    private final LlmModelRepository llmModelRepository;
    private final AgentRepository agentRepository;
    private final AuthUserUtil authUserUtil;

    public ConversationService(
            ConversationRepository repository,
            ConversationMapper mapper,
            ConversationQueryProfile queryProfile,
            PageableFactory<ConversationEntity> pageableFactory,
            QueryPredicateBuilder<ConversationEntity> queryPredicateBuilder,
            LlmModelRepository llmModelRepository,
            AgentRepository agentRepository,
            AuthUserUtil authUserUtil
    ) {
        super(repository, mapper, queryProfile, pageableFactory, queryPredicateBuilder);
        this.conversationRepository = repository;
        this.conversationMapper = mapper;
        this.llmModelRepository = llmModelRepository;
        this.agentRepository = agentRepository;
        this.authUserUtil = authUserUtil;

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationMiniDTO insert(ConversationForm form) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        LlmModelEntity model = llmModelRepository.findByIdAndIsEnabledTrue(form.getModelId())
                .orElseThrow(() -> new ItemNotFoundException("LLM model not found or is disabled."));
        AgentEntity agent = null;
        if (form.getAgentId() != null) {
            agent = agentRepository.findByIdAndOwnerId(form.getAgentId(), currentEmployee.getId())
                    .orElseThrow(() -> new ItemNotFoundException("Agent not found or not owned by current employee."));
        }
        String title = (form.getTitle() == null || form.getTitle().isBlank())
                ? "New Conversation"
                : form.getTitle();
        ConversationEntity entity = conversationMapper.toEntity(form);
        entity.setTitle(title);
        entity.setEmployee(currentEmployee);
        entity.setCurrentModel(model);
        entity.setAgent(agent);  // null for general conversation
        return conversationMapper.toSmallDTO(conversationRepository.save(entity));
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationDTO getOne(Long id) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        return conversationRepository.findByIdAndEmployeeId(id, currentEmployee.getId())
                .map(conversationMapper::toDTO)
                .orElseThrow(ItemNotFoundException::new);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationDTO delete(Long id) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        ConversationEntity entity = conversationRepository.findByIdAndEmployeeId(id, currentEmployee.getId())
                .orElseThrow(ItemNotFoundException::new);
        conversationRepository.delete(entity);
        return conversationMapper.toDTO(entity);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public Page<ConversationListDTO> getListPage(PageableRequest request) throws InvalidQueryRequestException {
        // Cannot declare ItemNotFoundException — interface only declares InvalidQueryRequestException.
        // Use ResponseStatusException as the fallback for the authenticated-employee-not-found case.
        EmployeeEntity currentEmployee = authUserUtil.getAuthUserEmployeeEntity()
                .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND, "Authenticated employee not found."));
        Predicate basePredicate = queryPredicateBuilder.build(request, queryProfile);
        Predicate ownerPredicate = QConversationEntity.conversationEntity.employee.id.eq(currentEmployee.getId());
        // BooleanBuilder(null) is a valid empty builder; getValue() returns null for empty AND,
        // which QueryDSL treats as "no predicate" (returns all rows before the ownership AND is applied).
        Predicate combined = new BooleanBuilder(basePredicate).and(ownerPredicate).getValue();
        PageRequest pageable = pageableFactory.create(request, queryProfile);
        return conversationRepository.findAll(combined, pageable).map(conversationMapper::toListDTO);
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public Collection<ConversationDTO> getAll() {
        throw new ResponseStatusException(HttpStatus.METHOD_NOT_ALLOWED,
                "Use POST /conversation/list for scoped conversation retrieval.");
    }

    @Override
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationDTO update(Long id, ConversationForm form) {
        throw new ResponseStatusException(HttpStatus.METHOD_NOT_ALLOWED,
                "Use PATCH /conversation/{id}/title or PATCH /conversation/{id}/model.");
    }

    @Transactional
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationDTO switchModel(Long id, Long modelId) throws ItemNotFoundException {
        EmployeeEntity currentEmployee = currentEmployee();
        ConversationEntity conversation = conversationRepository.findByIdAndEmployeeId(id, currentEmployee.getId())
                .orElseThrow(ItemNotFoundException::new);
        LlmModelEntity model = llmModelRepository.findByIdAndIsEnabledTrue(modelId)
                .orElseThrow(() -> new ItemNotFoundException("LLM model not found or is disabled."));
        conversation.setCurrentModel(model);
        return conversationMapper.toDTO(conversationRepository.save(conversation));
    }

    @Transactional
    @PreAuthorize("hasRole('EMPLOYEE')")
    public ConversationDTO updateTitle(Long id, String title) throws ItemNotFoundException, InvalidInsertDetails {
        if (title == null || title.isBlank()) {
            throw new InvalidInsertDetails("Conversation title must not be blank.");
        }
        EmployeeEntity currentEmployee = currentEmployee();
        ConversationEntity conversation = conversationRepository.findByIdAndEmployeeId(id, currentEmployee.getId())
                .orElseThrow(ItemNotFoundException::new);
        conversation.setTitle(title);
        return conversationMapper.toDTO(conversationRepository.save(conversation));
    }

    private EmployeeEntity currentEmployee() throws ItemNotFoundException {
        return authUserUtil.getAuthUserEmployeeEntity()
                .orElseThrow(() -> new ItemNotFoundException("Authenticated employee not found."));
    }
}

#### Edge Cases

1. **`update()` signature vs `DefaultServiceImplements.update()`**: the base class declares `update(ID id, FORM form) throws ItemNotFoundException, InvalidInsertDetails, ItemAlreadyExist`. The override can narrow the declared exceptions (throw fewer) but not widen them. Throwing `ResponseStatusException` (unchecked) is always permitted — no additional `throws` clause needed.
2. **`entity.setAgent(null)` for general conversations**: when `form.getAgentId()` is null, `agent` is null. `entity.setAgent(null)` explicitly clears the field. Hibernate generates `INSERT INTO conversation (..., agent_id, ...) VALUES (..., NULL, ...)`.
3. **Why `insert()` doesn't call `super.insert()`**: the base `insert()` calls `mapper.toEntity(form)` and `repository.save()` directly — it has no knowledge of the employee FK, model lookup, or agent validation. The full override is required.
4. **`switchModel` and `updateTitle` are not part of `DefaultService`**: they are additional methods on `ConversationService`. Spring's `@PreAuthorize` applies to them because `ConversationService` is a Spring-managed bean and Spring Security wraps it with a proxy. Method security is active on all public methods of `@Service` beans when `@EnableMethodSecurity` is in effect (it is — verified by the existing `AgentService` tests).
5. **`conversationRepository.save()` in `switchModel` and `updateTitle`**: calling `save()` on an already-managed entity is equivalent to `merge()`. Hibernate detects the dirty field (currentModel or title) and issues an UPDATE. `@PreUpdate` on the entity fires, refreshing `updatedAt`. This is the correct mutation pattern — identical to AgentService's `update()`.
6. **`delete()` reads entity before deleting**: `findByIdAndEmployeeId` loads the entity so it can be mapped to `ConversationDTO` before deletion. The mapper calls are safe because the entity is still in the persistence context. After `conversationRepository.delete(entity)`, Hibernate issues `DELETE FROM conversation WHERE id = ?` — at this point the entity is detached, but `conversationMapper.toDTO(entity)` only reads plain field values and FK proxy IDs (already populated), so no `LazyInitializationException` can occur.
7. **`switchModel` and `updateTitle` require explicit `@Transactional`**: `DefaultServiceImplements` has a class-level `@Transactional` annotation, but this only covers methods defined in that class. `switchModel` and `updateTitle` are defined only in `ConversationService` — they are not in any parent class — so they do NOT inherit the parent's transaction boundary. Each method must declare its own `@Transactional` to ensure the load+modify+save sequence is atomic. Without it, a save failure would not roll back the prior load, and the entity state could diverge from the DB in the current persistence context.

### Step 6: Create ConversationController (Phase 3, Step 3.3)

**Goal:** Map the Conversation endpoints. Inherits standard CRUD from `DefaultController`; adds two PATCH mappings via the concrete `conversationService` field.

**Dependencies:** `ConversationService` must exist (Step 3). All DTOs and forms from Task 2 must exist.

- [ ] Create `ConversationController.java` in `backend/src/main/java/com/agentForgeBackend/models/conversation/`

**Why the dual-injection pattern**: `DefaultController` holds `defaultService` typed as `DefaultService<ConversationDTO, ConversationMiniDTO, ConversationListDTO, ConversationForm, Long>`. `DefaultService` does not declare `switchModel` or `updateTitle`. A cast would be fragile. Storing a concrete `ConversationService` field alongside the inherited field is the established pattern — identical to `LlmModelController`.

#### Implementation

```java
package com.agentForgeBackend.models.conversation;

import com.agentForgeBackend.exceptions.InvalidInsertDetails;
import com.agentForgeBackend.exceptions.ItemNotFoundException;
import com.agentForgeBackend.shared.defaultImplements.DefaultController;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/conversation")
public class ConversationController extends DefaultController<ConversationDTO, ConversationMiniDTO, ConversationListDTO, ConversationForm, Long> {

    private final ConversationService conversationService;

    public ConversationController(ConversationService service) {
        super(service);
        this.conversationService = service;
    }

    @PatchMapping("/{id}/model")
    public ResponseEntity<ConversationDTO> switchModel(
            @PathVariable Long id,
            @Valid @RequestBody ConversationModelSwitchForm form) throws ItemNotFoundException {
        return ResponseEntity.ok(conversationService.switchModel(id, form.getModelId()));
    }

    @PatchMapping("/{id}/title")
    public ResponseEntity<ConversationDTO> updateTitle(
            @PathVariable Long id,
            @Valid @RequestBody ConversationTitleForm form) throws ItemNotFoundException, InvalidInsertDetails {
        return ResponseEntity.ok(conversationService.updateTitle(id, form.getTitle()));
    }
}
```

#### Edge Cases

1. **Inherited `PUT /{id}`** calls `defaultService.update(id, form)` → `ConversationService.update()` → throws `ResponseStatusException(405)`. The controller does not need to override `PUT /{id}` — the service override handles it transparently.
2. **Inherited `GET /`** calls `defaultService.getAll()` → `ConversationService.getAll()` → throws `ResponseStatusException(405)`. Same pattern.
3. **`@Valid` on PATCH forms**: `ConversationModelSwitchForm.modelId` has `@NotNull`; `ConversationTitleForm.title` has `@NotBlank`. `@Valid` causes Spring to invoke Bean Validation before the method body runs. A missing or blank field produces 400 from `GlobalExceptionHandler.handleValidationException()`.
4. **No `@PreAuthorize` on controller methods**: security is enforced at two layers — HTTP (`hasRole("EMPLOYEE")` from Task 1) and service (`@PreAuthorize("hasRole('EMPLOYEE')")` on all `ConversationService` methods). The controller itself is a thin coordinator.

## Design Decisions

**Decision 1: `ConversationQueryProfile` field map uses `Map.of` (not `Map.ofEntries`)**
- **Why:** 5 entries is within `Map.of`'s 10-entry limit. The identical pattern is used in `AgentQueryProfile` (4 entries). Consistency with prior art outweighs the hypothetical future case of needing more fields — at which point the developer can switch to `Map.ofEntries` easily.
- **Alternatives considered:** `Map.ofEntries(entry(...), ...)`. Not wrong, but introduces unnecessary verbosity for 5 entries.

**Decision 2: `ConversationService.insert()` performs agent lookup in a single `findByIdAndOwnerId` call (not separate exists + fetch calls)**
- **Why:** A single call combines existence check and ownership check into one DB query. If the agent does not exist or belongs to another employee, `Optional.empty()` is returned and `ItemNotFoundException` is thrown — identical behavior either way, consistent with `getOne`/`delete` patterns. This is the minimum number of DB roundtrips for this validation.
- **Alternatives considered:** `agentRepository.existsByIdAndOwnerId(agentId, employeeId)` (confirm) + `agentRepository.findById(agentId)` (fetch). Rejected — two DB queries for one validation, and `findById` would succeed for non-owned agents (breaking the ownership contract if the existence check were accidentally skipped in a future refactor).

**Decision 3: `getAll()` and `update()` both override with `ResponseStatusException(405)` — no `super` call**
- **Why:** `super.update()` is documented in `known-issues.md` as a no-op bug (loads entity, saves without applying form data). Calling it would silently accept the mutation request and return stale data. `super.getAll()` would return all conversations from all employees — a cross-tenant data leak. Both must be overridden to throw 405.
- **Alternatives considered:** Not overriding `update()` and relying on `super.update()`'s behavior. Rejected — the known-issues.md entry confirms the base implementation is broken; the override is the correct fix for this domain.

**Decision 4: `switchModel` and `updateTitle` are NOT added to `DefaultService` interface**
- **Why:** They are domain-specific operations that do not exist on any other entity. Adding them to the generic interface would force all `DefaultService` implementations to provide stubs — violating ISP. The dual-injection pattern in `ConversationController` (concrete `conversationService` field) is the established extension mechanism for this codebase.
- **Alternatives considered:** Adding the methods to `DefaultService` with default `throw new UnsupportedOperationException()`. Rejected — ISP violation; shallow implementations across the codebase.

**Decision 5: `updateTitle` validates `title` in the service body even though `ConversationTitleForm.title` has `@NotBlank`**
- **Why:** `@NotBlank` is enforced by `@Valid` in the controller — it is a Jakarta Validation annotation applied at the HTTP boundary. When `updateTitle(Long id, String title)` is called directly (e.g., from `ConversationServiceIntegrationTest`), `@Valid` does not run. The service guard ensures the business rule is enforced regardless of whether the call path goes through the controller. Defense-in-depth at the service layer.
- **Alternatives considered:** Relying solely on `@NotBlank` on the form. Rejected — service tests (and future callers) bypass the controller layer. The guard is 2 lines and has zero negative side effects.

**Decision 6: setUp clears `AppSettingsEntity.defaultModel` before `llmModelRepository.deleteAll()`**
- **Why:** `AppSettingsEntity.defaultModel` is a nullable FK to `LlmModelEntity`. Without clearing it first, `llmModelRepository.deleteAll()` throws `DataIntegrityViolationException` on H2 because `app_settings.default_model_id` references the model being deleted. This is a dependency unique to tests that delete LLM models — the AgentControllerTest and AgentServiceTest don't delete LLM models so they never encountered it.
- **Alternatives considered:** Not deleting LLM models in setUp (create new ones with unique IDs). Rejected — accumulating models across test methods with the same `modelId` would hit the unique constraint on the second setUp. Using `System.currentTimeMillis()` in `modelId` would work but produces non-deterministic test data that is harder to reason about.

### Test isolation: FK constraint fix for pre-existing test classes

The introduction of `ConversationEntity` (which has a non-null FK `current_model_id` → `llm_model` and a non-null FK `employee_id` → `employee`) caused FK constraint violations in pre-existing test classes that delete LLM models or employees in their `setUp()` method but do not delete conversations first. The alphabetic test ordering means Conversation test classes ("Co") run before LlmModel tests ("Ll") and Employee tests ("Em"), leaving committed rows in H2.

**Files patched (pre-existing, outside original Task scope):**

- `LlmModelServiceCrudIntegrationTest.java` — added `conversationRepository.deleteAll()` before `llmModelRepository.deleteAll()` in setUp
- `LlmModelServiceListQueryIntegrationTest.java` — same
- `LlmModelControllerTest.java` — same
- `AppSettingsServiceIntegrationTest.java` — added `conversationRepository.deleteAll()` and `agentRepository.deleteAll()` before `llmModelRepository.deleteAll()` and `employeeRepository.deleteAll()`
- `AppSettingsControllerTest.java` — same
- `EmployeeLoginJwtTest.java` — added `conversationRepository.deleteAll()` and `agentRepository.deleteAll()` before `employeeRepository.deleteAll()`
- `EmployeeControllerListEndpointTest.java` — same
- `EmployeeServiceCrudIntegrationTest.java` — same
- `EmployeeServiceListQueryIntegrationTest.java` — same

This is a systemic FK ordering issue: any test class that deletes `llm_model` or `employee` rows in setUp must delete `conversation` and `agent` rows first (in that order). Future test classes that perform entity cleanup should follow the FK-safe delete order:
1. `conversationRepository.deleteAll()` (has FKs to employee, agent, llm_model)
2. `agentRepository.deleteAll()` (has FK to employee)
3. `llmModelRepository.deleteAll()` (referenced by conversation and app_settings)
4. `employeeRepository.deleteAll()` (referenced by conversation, agent, app_settings.updatedBy)
