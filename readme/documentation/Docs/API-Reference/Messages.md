# Messages API

Base path: `/conversation/{conversationId}/messages`
Frontend calls: `/api/conversation/{conversationId}/messages`
Auth required: **ROLE_EMPLOYEE**. Only messages belonging to conversations owned by the authenticated employee are accessible.

Messages are created exclusively via the WebSocket chat flow — this REST endpoint is **read-only**. See [[WebSocket-Chat]] for how messages are produced.

---

## GET /conversation/{conversationId}/messages

Returns the full message history for a conversation, ordered by `createdAt` ascending (chronological order).

Returns 404 if the conversation does not exist or is not owned by the authenticated employee.

**Response 200** — `MessageDTO[]`
```json
[
  {
    "id": 1,
    "conversationId": 12,
    "role": "USER",
    "content": "What is the capital of France?",
    "llmModelId": null,
    "inputTokens": null,
    "outputTokens": null,
    "createdAt": "2026-06-26T10:00:00"
  },
  {
    "id": 2,
    "conversationId": 12,
    "role": "ASSISTANT",
    "content": "The capital of France is Paris.",
    "llmModelId": 2,
    "inputTokens": 12,
    "outputTokens": 9,
    "createdAt": "2026-06-26T10:00:02"
  }
]
```

## Schemas

### MessageDTO
| Field | Type | Notes |
|-------|------|-------|
| `id` | long | |
| `conversationId` | long | |
| `role` | enum | `USER` or `ASSISTANT` |
| `content` | string | Full message text |
| `llmModelId` | long (nullable) | Null for USER messages; set for ASSISTANT messages |
| `inputTokens` | int (nullable) | Null for USER messages |
| `outputTokens` | int (nullable) | Null for USER messages |
| `createdAt` | datetime | |

### MessageRole enum
| Value | Description |
|-------|-------------|
| `USER` | Message sent by the employee |
| `ASSISTANT` | Message generated by the LLM |

There is no `SYSTEM` role in persisted messages. `initPrompt` and `recurrentPrompt` are applied at request time and never stored.

---

## Notes

- The history array is always sorted ascending by `createdAt` — ready to pass directly to the LLM as context.
- `llmModelId` on ASSISTANT messages records which model produced the response. If the model was later deleted, the ID remains (no FK cascade; the message is immutable).
- Token counts reflect what OpenRouter reported for that specific turn. Useful for usage tracking.
